# ETFE five-DTE purchase limit — October 4, 2026

The user directs: options ETFE trades must be **5 DTE or less**. This successor
reduces the existing maximum at every new entry and roll purchase from nine to
five **calendar days**, retaining the previously explicit one-day minimum.
Zero-DTE purchases remain excluded; no zero-DTE authorization is inferred.

The selected machine scope is [v3](ETFE_SCOPE_ALPACA_20261004.json). Actual DTE is
expiration date minus the purchase-attempt date in America/New_York, including
weekends/holidays. Recompute it at the actual attempt, including delayed attempts
and rolls; a target of five cannot choose an actual six-, seven-, eight- or
nine-DTE contract. If no eligible expiry exists, record no eligible contract.

Default targets remain 1/5. The conditionally enabled weekly target extension
becomes 2/4; **target 7 is removed**, not clamped to five. Dated weekly eligibility
is still required. Every strategy family remains in scope. This cap does not
alter the 20-family/25,353 ticker-variant catalog, which excludes DTE dimensions.

`nn_meta/etfe/purchase_policy.py` supplies a tested entry/roll DTE guard. Passing
it does not satisfy price/cash/session/identity guards or imply a complete
execution engine. The prior [execution declaration](ETFE_EXECUTION_20261003.md)
is overridden only for actual purchase range and weekly target 7.

The inherited `dte_frac` formula divided by nine. For the new ETFE feature
schema, its resolved formula is **actual_calendar_DTE_at_decision / 5**. This
explicit override to the [declared registry](ETFE_FEATURE_MAP_20261003.json) is
stored in v3 scope and tested; it is not an in-place modification of the frozen
v1 registry or a relabeling of old feature arrays. Final feature/schema freeze
must materialize the resolved v3 mapping and hash before training.

Context-only option downloads may still use the declared 1–45 DTE surface;
download eligibility and purchase eligibility are different. The freshly
downloaded October 2 same-day contracts are transport-validation samples only,
not eligible entries. No existing model/trade was created from them. Raw sample
capture plans retain their identities and need not be redownloaded for this rule.

All other accepted VWAP, stop, portfolio, cost, universe, timeframe and fixed-end
rules remain. Fresh Alpaca acquisition follows the
[collection successor](ETFE_FRESH_ACQUISITION_20261003.md). Earlier midpoint/v2
setups stay immutable; the selected v3 setup has its own scope/source hashes.
