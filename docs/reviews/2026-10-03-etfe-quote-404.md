# ETFE historical quote 404 investigation — October 3, 2026

**Finding:** `/v1beta1/options/quotes` is an unsupported public Alpaca endpoint.
The observed 404s are not missing SPY/QQQ/VOO history rows, bad credentials or an
OPRA entitlement failure. Alpaca's public options API supplies latest quotes,
but does not supply the historical bid/ask windows required by ETFE's inherited
execution and quote-feature contract. This resolves the diagnostic, not ETFE-0.

## Evidence

On June 17, 2026, Alpaca staff member Gergely_Alpaca answered a question about
historical option quotes being on the roadmap: **“No, it isn’t.”** The response
directed users to Massive. [Official staff response](https://forum.alpaca.markets/t/historical-option-quote-question/19029).
This is evidence of the provider limitation; Massive remains excluded by the user.

The documented quote route is
[`/v1beta1/options/quotes/latest`](https://docs.alpaca.markets/us/reference/optionlatestquotes),
with symbols/feed parameters and no historical start/end range. The
[chain endpoint](https://docs.alpaca.markets/us/reference/optionchain) also returns
latest snapshots. Its `updated_since` parameter filters snapshot freshness; it
does not retrieve an as-of historical chain or replay quotes. Installed
alpaca-py 0.44.0 has historical bars/trades and latest quote/snapshot methods,
but no historical option-quote method.

At 18:41:55 Central on October 3, 13 bounded authenticated GETs completed with
zero transport failures using the same data credential pair for every request:

| Control | HTTP | Observation |
| --- | --- | --- |
| Historical SPY trade, January 18, 2024 | 200 | Actual trade row returned |
| Latest OPRA chain for each of SPY, QQQ, VOO | 200 × 3 | Contract and latest bid/ask returned |
| Latest OPRA quote for each returned contract | 200 × 3 | Nonempty bid/ask, sizes and timestamps |
| Historical quotes for those same three contracts, October 2, 2026 | 404 × 3 | Same `Not Found` body |
| Historical quote route without any query parameters | 404 | Same `Not Found` body |
| SPY historical quote request without feed / with indicative feed | 404 × 2 | Same `Not Found` body |

Every 404 body has SHA256
`8699bf1eda7e016dec3efeff8db5e3400183e9ebf6ce42355b97b843def2b035`.
The current-contract controls eliminate the old-expired-contract explanation
for the earlier three 404s. The successful OPRA controls establish access for
these requests; they do not admit full history, quote quality or future capacity.

Latest quote timestamps are October 2 because the probe ran on Saturday.
That is one retained latest observation per contract, not retrievable quote
history throughout October 2 or earlier. Snapshots and trades cannot recover
missing bid/ask sizes, spreads or quote-age windows.

## Reproducibility and limits

- Independent diagnostic: `scripts/diagnose_etfe_quotes.py`; fixed GET allowlist,
  maximum 13 requests, 2 MiB/response, no redirects, credential echo protection,
  exclusive output creation, setup integrity check before requests.
- Evidence: `nn_meta/validation/etfe-setup-20261003-r0/probe-quotes-r1/DIAGNOSTIC.json`
  plus hashed raw bodies and per-request receipts. Sandbox-only failed r0 is
  retained separately and is not provider evidence.
- Portable [review receipt](2026-10-03-etfe-quote-404.json) preserves response bodies,
  parameters, timestamps, hashes, SDK method list and official source links.
- Actual live controls and all receipt/body/source hashes verified; original
  setup integrity still passes. Frozen setup producer sources were not changed.
- No private/bespoke Alpaca delivery was investigated. Such a possibility would
  need affirmative provider evidence, not assumed availability or blind retries.

## Consequence for the selected scope

`ETFE.quote-diagnosis` is complete. `ETFE.provider-contract` remains open.
The fixed historical window, Alpaca-only options policy and inherited
quote-dependent methodology cannot currently all be satisfied by this public API.
No further retries of this route are useful without new provider evidence.

A resolution needs either evidenced Alpaca historical delivery outside this
public API or an explicit user-approved scope/methodology change. Historical
trade/bar modeling would be a changed execution/feature contract, not equivalent
to bid/ask midpoint simulation. Prospective recording supplies only future
observations and cannot backfill the fixed window ending October 2. No change
to provider, dates, features, strategies or admission status was made here.
